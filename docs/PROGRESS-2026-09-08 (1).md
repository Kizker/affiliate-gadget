# Progress Report - 8 September 2026 (Checkout Security, Architecture Hardening, Product-to-Store Chat & Real-Time Sync - Sprint 1, 2, 3, 4 & 5)

## 📋 Overview

Sesi rekayasa perangkat lunak ini berfokus pada audit keamanan mendalam (_deep security audit_), penutupan kerentanan kritis (_vulnerability remediation_), perbaikan integritas data inventori, optimasi performa _end-to-end_ pada alur transaksi Checkout, serta implementasi fitur interaksi langsung pelanggan ke toko fisik cabang (_Product-to-Store Direct Chat_) dan stabilisasi obrolan real-time di platform Affiliate Gadget.

Seluruh temuan risiko dan fitur baru dikelompokkan dan diselesaikan secara tuntas dalam 5 siklus sprint teknis:

- **Sprint 1 (Fondasi Keamanan Kritis)**: Penanganan kebocoran state keranjang multi-user, pembatasan laju request (_rate limiting_ ganda), kalkulasi harga & logistik terproteksi di sisi server (_anti-tampering_), dan pencegahan _race condition_ stok unit via transaksi atomik database.
- **Sprint 2 (Validasi Data, IDOR Prevention & UX Hardening)**: Eliminasi kerentanan _Insecure Direct Object References_ (IDOR) pada rute pesanan, penegakan skema validasi Zod ketat, eliminasi query N+1 pada konfirmasi pesanan jamak, penegakan persetujuan Syarat & Ketentuan legal, perlindungan autentikasi rekening bank, sinkronisasi penghapusan paralel dengan mekanisme _state rollback_, dan penghapusan fallback rekening hardcoded.
- **Sprint 3 (Checkout Hardening, UI Polish & Idempotency)**: Penomoran pesanan ber-entropi tinggi anti-tabrakan (_collision-proof order number_) dengan auto-retry Prisma P2002, standardisasi `CHECKOUT_ERROR_CODES` & `CheckoutError`, guard `storeId: null` untuk mencegah order yatim piatu, kalkulasi dinamis bonus 3-in-1 dari database produk, eliminasi 100% tipe `any`, sub-toggle pilihan paket kurir JNE (REG vs YES) di UI checkout, dan perlindungan double-submit / replays via Redis Idempotency Key (`X-Idempotency-Key`).
- **Sprint 4 (Product-to-Store Chat Integration)**: Arsitektur relasi langsung `storeId` pada model `AdminChatRoom`, endpoint API `POST /api/customer/chat/store-room` untuk auto-create/open kamar chat tanpa order, pembuatan pesan pertama referensi produk otomatis atomik (`product_reference`), tombol interaktif "Chat Toko" di detail produk dengan proteksi sesi & URL context parameters, auto-open conversation di `/dashboard/customer/chat` dengan Next.js 15 Suspense boundary, pencegahan duplikasi pesan produk identik, serta preview sidebar & judul toko cabang mandiri.
- **Sprint 5 (Real-Time Chat Polish, Multi-Product Consistency & Router Synchronization)**: Pencegahan refresh/wipe pesan optimistik saat kirim pesan via `isSendingRef`, pembaruan algoritma pengecekan duplikasi `productId` di backend `store-room`, penanganan multi-produk di toko yang sama secara berurutan, siklus hidup `loadedRoomIdRef` & auto-clean URL via `router.replace` tanpa desinkronisasi Next.js App Router, serta tombol aksi "Chat Toko" konsisten di homepage (`section-featured-gadgets.tsx`).

### 4. **Atomic Inventory Decrement & Race Condition Protection (CRIT-01)**

- **Status**: ✅ Completed
- **File Modified**: [`src/app/api/checkout/route.ts`](file:///c:/.PROJECT/affiliate-gadget/src/app/api/checkout/route.ts)

#### Changes Made:

- **Eliminasi Read-Then-Write Flaw**: Mengganti pengecekan `product.stock >= qty` terpisah menjadi transaksi atomik level basis data di dalam blok `prisma.$transaction`.
- **Eksekusi `updateMany` Bersyarat**: Menggunakan klausa SQL `WHERE id = ... AND stock >= quantity` secara atomik.
- **Auto-Rollback pada Kegagalan**: Jika hasil eksekusi baris terpengaruh bernilai 0 (stok habis diserobot transaksi bersamaan), transaksi dibatalkan seketika dan server merespons dengan status `409 Conflict`.

#### Code Implementation:

```typescript
const stockUpdate = await tx.product.updateMany({
  where: {
    id: p.id,
    stock: { gte: item.quantity },
  },
  data: {
    stock: { decrement: item.quantity },
  },
})

if (stockUpdate.count === 0) {
  throw new Error(`STOK_HABIS:${p.name}`)
}
```

## 🔧 Technical Details

### Transaksi Atomik Database (Prisma PostgreSQL):

```typescript
await prisma.$transaction(async (tx) => {
  // Pengurangan stok bersyarat atomik
  const res = await tx.product.updateMany({
    where: { id: p.id, stock: { gte: item.quantity } },
    data: { stock: { decrement: item.quantity } },
  })
  if (res.count === 0) throw new Error('Stok tidak mencukupi')

  // Pembuatan order dan invoice
  return await tx.order.create({
    /* ... */
  })
})
```

### Konfigurasi Rate Limiting (Redis Sliding Window):

- **User Key Pattern**: `checkout:user:{userId}` (Limit: 5 request / 60 detik)
- **IP Key Pattern**: `checkout:ip:{clientIp}` (Limit: 10 request / 600 detik)

## 🐛 Issues Fixed

### 1. Manipulasi Harga Checkout oleh Klien (CRIT-02)

- **Problem**: Pengguna jahat dapat memodifikasi payload JSON subtotal atau ongkir sebelum dikirim.
- **Solution**: Rekalkulasi total menyeluruh di sisi server berdasarkan basis data resmi.

### 2. Kondisi Balapan Pengurangan Stok / Overselling (CRIT-01)

- **Problem**: Pengecekan stok non-atomik memungkinkan beberapa pembeli membeli unit gadget second langka yang tersisa 1.
- **Solution**: Atomic update `stock: { decrement: quantity }` dengan syarat `stock: { gte: quantity }` di dalam Prisma transaction.

### 3. Kebocoran Data Pesanan Antar Pengguna / IDOR (CRIT-04)

- **Problem**: Pengguna dapat menebak atau mengganti parameter URL `orderId` untuk melihat detail transaksi, alamat rumah, dan nomor HP pelanggan lain.
- **Solution**: Query database dibatasi langsung berdasarkan `userId` atau `storeId` milik sesi aktif, merespons dengan 404 seragam jika tidak berhak.

### 4. Kebocoran Keranjang Akun Sebelumnya (CRIT-05)

- **Problem**: Data keranjang belanja user lama masih tersimpan di memori browser saat user baru login di komputer yang sama.
- **Solution**: Flush state lokal Zustand seketika saat pergantian `userId`.

### 5. N+1 Waterfalling pada Halaman Konfirmasi Pesanan (HIGH-04)

- **Problem**: Checkout multi-cabang (Multi-PT) yang menghasilkan beberapa pesanan memuat data secara lambat satu demi satu.
- **Solution**: Optimasi paralel menggunakan `Promise.allSettled` dengan pembatasan 10 pesanan.
